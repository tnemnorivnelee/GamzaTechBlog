# OpenAPI Generator 가 뭔데?
프론트 개발자는 백엔드의 API 명세를 보고 해당 API 를 어떻게 어떤 방식으로 사용하는지 확인 후 연동하는 작업을 하게 됩니다..

API 명세를 보는 편리한 방법 중 하나가 바로 **Swagger**라고 할 수 있습니다.

Swagger 도 충분히 API 명세 파일을 보는 것보다는 시각적으로 프론트에게 엄청난 편리함을 제공합니다.

그래도 저는 이제까지 요청이나 응답에 대한 타입을 직접 수동으로 작성해왔습니다.

이를 자동화 시켜주는 것이 **API Generator** 라는 도구입니다.

프로젝트의 수정사항이 생길 때마다 API 명세는 수정되며, 이는 결국 프론트에서도 요청이나 응답에 대한 내용을 수정해야 했습니다.

이는 수동으로 타이핑해서 생기는 휴먼 에러(오타, 필드 누락 등) 을 야기할 수 있습니다.

API 명세를 바탕으로 생성해주는 API Generator 도구를 이용하면 **휴면 에러**를 줄일 수 있으며, 싱크를 더욱 쉽게 맞출 수 있으며, API 수정사항이 생기더라도 **업데이트**만 하면 바로 반영하여 사용할 수 있다는 장점이 있습니다.

이는 프론트 개발자가 API 연동에 투자되는 시간을 줄여 **다른 기능 개발**에 더욱 집중할 수 있게 됩니다.

# 적용 방법
현재 감기블 프로젝트는 Next.js App router 방식을 이용하며 API Generator 라이브러리는 [openapi-generator-cli](https://github.com/OpenAPITools/openapi-generator-cli) 를 적용한 상태입니다!

라이브러리를 설치하고, 생성 명령어를 실행하면 아래와 같이 프로젝트 내부에 파일이 생성됩니다.

![Uploaded Image](https://gamzatech-bucket.s3.ap-northeast-2.amazonaws.com/post-images/73/14c75db4-2a90-4f4a-b608-192e7ef3f38d_image.png)

위의 사진 처럼 src/generated/api/models 부분에 API 명세를 기반으로 생성되어 바로 적용할 수 있도록 만들어집니다.

![Uploaded Image](https://gamzatech-bucket.s3.ap-northeast-2.amazonaws.com/post-images/73/8fe4d00a-fb9a-4ca9-a2cd-ac708a3e2a28_image.png)

해당 사진은 API 명세를 기반으로 생성된 ResponseDto.ts 코드 파일의 일부입니다.

이제 프론트 개발자는 해당 인터페이스 코드를 바로 적용하면 되는 겁니다..!!

일단 저는 API Generator 를 도입하면서 API 인터페이스 일관성을 맞추기 위해 적용했다는 부분에서는 성공했다고 생각합니다.

API Generator 로 생성된 다른 파일들을 살펴보니 API 호출을 위한 함수까지도 자동으로 생성되는 것 같네요. 이런 부분까지 활용한다면 프론트 개발자는 API 연동에 있어서 시간을 훨씬 절약할 수 있을 거라고 생각합니다.

아직 감기블 프로젝트에는 API Generator 로 생성된 타입 인터페이스 파일만 적용하고 있지만, 추후에 Next.js 의 기능을 활용이 가능하다면 API 관련 함수까지 적용할 예정입니다.
